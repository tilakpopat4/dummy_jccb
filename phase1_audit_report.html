Executive Audit Finding: The 123,000+ Firestore read spike is the direct mathematical consequence of unmanaged client-side polling loops running at 5-second intervals across 120+ browser sessions, combined with unbounded real-time snapshot listeners downloading entire database collections without server-side filtering or pagination.

3. Security & Multi-Tenancy Flaws in Current Architecture

Critical Security Finding (firestore.rules):
Line 5-7 in firestore.rules: match /{document=**} { allow read, write: if true; }
The production database currently has completely open read and write access. Any employee or connected client can read, update, or delete loans, rates, and audit logs belonging to any other branch.
  • No Branch-Level Isolation: Branch managers from Branch 01 (Azad Chowk) can read and modify loan applications created by Branch 17 (Rajkot).
  • Client-Side Master Overwrite Risk: Every 5 seconds, if a client's local storage contains master records, syncCloudData() attempts to push them back up via saveSettings(), saveRules(), and saveValuersList(), leading to race conditions between branch terminals.
  • No Immutability on Security Audit Logs: Audit log documents in audit_logs can be deleted or overwritten by anyone with client access.

4. Supabase & PostgreSQL Migration Roadmap

Migrating to PostgreSQL + Supabase will resolve the root architectural problems at the database engine level, not just swap API calls.
Area Current Firestore Implementation Target Supabase (PostgreSQL) Design
Data Synchronization Aggressive 5-second polling (setInterval) across all 120+ client terminals. Event-driven Supabase Realtime WebSocket channels subscribed only to relevant events (rates change, central announcements). Zero polling loops.
Branch Data Isolation Full collection downloaded to client; filtered via JavaScript in browser memory. Postgres Row Level Security (RLS): WHERE branch_id = auth.jwt() ->> 'branch_id' enforced automatically by PostgreSQL.
Query Pagination Unbounded full table reads on loans and customers. Explicit server-side SQL pagination: .select('*').eq('branch_id', id).order('created_at', { ascending: false }).range(0, 49).
Device Presence / Heartbeat 30s read-before-write to active_sessions document generating 345k reads/day. Supabase Realtime Presence (in-memory WebSocket presence tracking, 0 database disk reads) with optional SQL UPSERT without read check.
Listener Lifecycle Ignored unsubscribe handlers leaking memory and connections. Managed channel tracking with explicit supabase.removeChannel(channel) on component unmount and view switches.
Audit Log Security Open collection modifiable by any authenticated or anonymous client. Postgres APPEND-ONLY table with RLS policy FOR INSERT WITH CHECK (true) and FOR UPDATE, DELETE USING (false).
